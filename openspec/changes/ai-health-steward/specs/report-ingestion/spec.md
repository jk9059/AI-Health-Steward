## ADDED Requirements

### Requirement: 报告上传
系统 SHALL 支持用户上传图片（JPG/PNG）和 PDF 格式的医疗报告，包括体检报告、化验单、处方单、病历等类型。

#### Scenario: 上传图片报告
- **WHEN** 用户在 WebUI 或飞书渠道上传一张化验单图片
- **THEN** 系统接收文件并进入多模态抽取流程

#### Scenario: 上传 PDF 报告
- **WHEN** 用户上传一份 PDF 格式的体检报告
- **THEN** 系统接收文件并进入多模态抽取流程

#### Scenario: 不支持的文件格式
- **WHEN** 用户上传非图片/PDF 文件（如 .docx）
- **THEN** 系统拒绝并提示"仅支持 JPG/PNG/PDF 格式"

### Requirement: 模型路由按输入类型分流
系统 SHALL 根据输入内容是否含视觉信息路由到不同模型类型：图片/PDF 必走多模态大模型；纯文字输入走文字大模型。

#### Scenario: 图片输入路由多模态
- **WHEN** 输入为图片或 PDF 文件
- **THEN** 系统调用多模态 API provider 进行处理

#### Scenario: 纯文字输入路由文字模型
- **WHEN** 输入为纯文本（手动录入、聊天内容）
- **THEN** 系统调用文字 API provider 或本地 LLM（按配置）

### Requirement: 多模态结构化抽取
系统 SHALL 调用多模态大模型对上传的报告进行结构化抽取，输出包含关键信息和标识的 JSON 数据，归入人维度健康画像对应字段族。

#### Scenario: 抽取化验单指标
- **WHEN** 上传一份血常规化验单
- **THEN** 多模态模型抽取指标名、数值、单位、参考范围、异常标识，输出结构化 JSON

#### Scenario: 抽取处方药品信息
- **WHEN** 上传一张处方单
- **THEN** 多模态模型抽取药品名称、剂量、频次、给药方式，归入 D 用药记录字段族

#### Scenario: 抽取结果需用户确认
- **WHEN** 多模态抽取完成
- **THEN** 系统展示抽取结果供用户确认，用户可编辑修正后才正式入档

### Requirement: 报告姓名识别与归属匹配
系统 SHALL 在多模态抽取时顺带识别报告上的姓名，与家庭成员进行匹配，自动归属到对应成员；匹配不上时默认归属为操作者本人；用户可手动覆盖归属。

#### Scenario: 姓名匹配成功自动归属
- **WHEN** 报告上识别出姓名"张三"，且家庭成员中有"张三"
- **THEN** 系统自动将报告数据归属到成员"张三"的画像

#### Scenario: 姓名匹配失败默认本人
- **WHEN** 报告上识别出姓名但无任何家庭成员匹配
- **THEN** 系统默认归属为操作者本人，并提示用户可手动修改归属

#### Scenario: 用户手动指定归属
- **WHEN** 用户在确认抽取结果时手动选择归属成员
- **THEN** 系统以用户指定为准，覆盖自动识别结果
 
### Requirement: 报告导入状态流转
系统 SHALL 为报告导入定义完整的状态机：已上传 → 抽取中 → 抽取完成 → 待确认 → 已入档 / 已拒绝 / 已取消。每个状态可被用户或系统观测，且只有合法的状态转换才被允许。
 
#### Scenario: 正常状态流转
- **WHEN** 用户上传一份报告并完成多模态抽取，用户确认抽取结果无误
- **THEN** 状态依次经过"已上传 → 抽取中 → 抽取完成 → 待确认 → 已入档"，数据正式写入健康画像
 
#### Scenario: 抽取中状态可取消
- **WHEN** 报告处于"抽取中"状态时用户主动取消
- **THEN** 系统终止抽取流程，将报告状态标记为"已取消"，不写入任何数据到健康画像
 
#### Scenario: 待确认状态超时自动标记过期
- **WHEN** 报告抽取完成后进入"待确认"状态，且用户在 24 小时内未进行确认或拒绝操作
- **THEN** 系统自动将该报告状态标记为"待确认-过期"，并通过飞书或 WebUI 通知用户"有报告待确认已过期，请前往确认"
 
#### Scenario: 用户拒绝抽取结果
- **WHEN** 用户在"待确认"状态查看抽取结果后选择拒绝
- **THEN** 系统将报告状态标记为"已拒绝"，不写入数据到健康画像，保留原始文件供用户重新上传或手动录入
 
#### Scenario: 抽取失败状态及重试
- **WHEN** 多模态抽取过程中发生失败（如 API 错误、结果质量极低），报告状态标记为"抽取失败"
- **THEN** 系统允许用户手动触发重试，重试时状态回到"抽取中"；若重试仍失败，用户可选择手动录入或放弃（标记"已取消"）
 
### Requirement: 报告导入异常处理
系统 SHALL 在报告导入流程的各环节处理异常情况，包括多模态服务不可用、文件过大、文件损坏、抽取结果异常、非医疗内容识别等，确保异常情况下用户获得明确提示且系统状态一致。
 
#### Scenario: 多模态 API 超时或失败
- **WHEN** 多模态抽取调用 API 超时或返回错误
- **THEN** 系统向用户提示"多模态服务暂不可用，请稍后重试"，报告保留在"已上传"状态，不进入"抽取中"状态，不产生部分写入数据
 
#### Scenario: 上传文件过大
- **WHEN** 用户上传的文件大小超过限制（如 20MB）
- **THEN** 系统在接收阶段即拒绝上传，向用户提示"文件过大，请上传 20MB 以内的文件"，不创建报告记录
 
#### Scenario: 损坏或无法识别的文件
- **WHEN** 用户上传的文件格式正确但内容损坏或无法被多模态模型解析
- **THEN** 系统将报告状态标记为"抽取失败"，向用户提示"文件无法识别，请重新上传清晰的报告图片或 PDF"
 
#### Scenario: 多模态抽取结果为空或质量极低
- **WHEN** 多模态抽取完成但返回结果为空，或抽取质量极低（如关键字段缺失率超过阈值）
- **THEN** 系统将报告状态标记为"抽取失败"，向用户提示"抽取结果质量不足，建议手动录入数据"，并提供手动录入入口
 
#### Scenario: 上传非医疗报告图片
- **WHEN** 用户上传的图片经多模态模型判断为非医疗内容（如风景照、聊天截图）
- **THEN** 系统在抽取结果中标注"非医疗内容"，向用户提示"该文件可能不是医疗报告，是否仍要入档"，由用户确认后决定是否继续入档流程
