## 第一轮阻塞性问题修复核对

### 阻塞1：数据模型未定义到字段级 → 已修复 ✅

design.md 新增 D8 决策，为 A-H 每个字段族列出了字段名、类型、单位、是否时序的表格化定义。字段数量：A(7) + B(9) + C(5) + D(7) + E(4) + F(4) + G(3) + H(4) = 43 个字段。逻辑模型与物理 schema 分离的说明到位。工程师现在可以直接映射为表结构。

### 阻塞2：参考范围数据源未定义 → 已修复 ✅

design.md 新增 D9 决策，定义了本地化 JSON 配置文件方案，按性别+年龄段分组，附数据结构示例和来源标注（中国成人血脂/高血压/糖尿病防治指南）。版本化管理规则清晰。标注"需医学团队确认"划清了工程与医学的边界。

### 阻塞3：异常路径大量缺失 → 已修复 ✅

四个 spec 文件共追加 7 个新 Requirement、24 个异常场景：
- report-ingestion：状态机（5 场景）+ 异常处理（5 场景）
- ai-consultation：意图路由异常处理（4 场景）
- channels：飞书异常处理（4 场景）+ 操作者身份识别（2 场景）
- health-profile：成员数据操作异常处理（4 场景）

核心异常路径已覆盖：API 失败、超时、空数据、并发冲突、重复消息、误删、意图识别错误等。

### 阻塞4：成功标准与护栏指标完全缺失 → 已修复 ✅

proposal.md 新增 Success Metrics 章节，四组可度量指标：
- 开源传播：star≥500、fork≥50、部署成功率≥80%
- 产品价值：使用超2周家庭≥20、画像数据≥30条/家庭、报告确认率≥70%
- AI 咨询质量：回答确认率≥60%、聊天抽取确认率≥70%
- 护栏负向：误导率<5%、数据错误率<1%、抽取失败率<15%、归属误判率<5%

每个指标有基线、目标值、验证周期。护栏指标完整。

### 阻塞5：报告导入状态机未定义 → 已修复 ✅

report-ingestion spec 新增"报告导入状态流转"Requirement，定义完整状态机：已上传 → 抽取中 → 抽取完成 → 待确认 → 已入档/已拒绝/已取消。含超时（24小时）、取消、重试场景。

## 残留问题（建议性，不阻塞）

### 残留1：工具接口签名未定义（工程可实施性）

**位置**：ai-consultation spec
**问题**：query_metrics / query_profile / query_abnormal / extract_and_save 等工具的名称已在场景中出现，但输入参数和返回格式未定义。工程师知道"要调用 query_metrics"，但不知道它接收什么参数、返回什么结构。
**建议**：在技术评审中确定工具接口签名，或在设计阶段补充。不阻塞需求评审。
**严重程度**：中

### 残留2：埋点事件清单未独立定义（可度量性）

**位置**：Success Metrics 章节
**问题**：成功标准中提到的"回答确认率""投诉率""抽取失败率"等指标需要埋点支撑，但 PRD 中没有独立的埋点事件清单。工程师不知道要埋哪些点。
**建议**：在技术评审中补充埋点事件清单，或由工程团队在实现阶段定义。开源项目可后期通过社区反馈优化埋点。
**严重程度**：低

### 残留3：健康科普意图的边界（医疗合规）

**位置**：ai-consultation spec "B 级内容正常输出"场景
**问题**：B 级场景提到"饮食建议、运动指导"属于常规科普正常输出，但某些饮食建议对特定疾病患者可能有害（如糖尿病患者的饮食建议）。B 级与 A 级的边界在"涉及特定用户画像时"可能模糊。
**建议**：在角色知识边界约束中补充——当 B 级内容涉及用户已有诊断时，升级为 A 级处理（附带警示）。
**严重程度**：低
