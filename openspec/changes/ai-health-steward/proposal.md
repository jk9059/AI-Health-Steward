## Why

家庭健康管理缺乏一个可私有化部署、数据自主可控的开源方案。现有商业产品（如讯飞晓医）能力完整但数据不在用户手中；而纯本地 LLM 方案在多模态健康报告处理上能力不足。我们需要一个以 WebUI 为主、支持多渠道资料收集、以多模态大模型为核心的结构化健康画像与咨询服务，且部署门槛足够低，开发者可以 fork 后快速跑起来。

## User Stories

**US-1：家庭健康管理者上传报告**

> 作为家庭健康管理者，我想要将体检报告、化验单拍照上传到系统，以便系统自动提取关键指标并归入对应家庭成员的健康画像，而不必手动逐条录入。

**US-2：家庭成员查看健康趋势**

> 作为家庭成员，我想要在 WebUI 上查看自己最近一段时间的血压、血糖等指标趋势图，以便了解健康变化方向，在体检或就医时心中有数。

**US-3：用户通过飞书随手丢报告**

> 作为飞书重度用户，我想要在飞书聊天里直接把报告图片发给 Bot，Bot 自动抽取并归档，以便我不用专门打开 WebUI 也能随手把报告存进系统。

**US-4：用户咨询健康问题**

> 作为已建立健康画像的用户，我想要用自然语言向 AI 询问"我最近的血压怎么样""血糖 6.5 正常吗"等问题，以便快速获得基于自己实际数据的健康参考，而不用翻找报告或搜索网页。

**US-5：家庭多成员档案管理**

> 作为家庭健康管理者，我想要为家中每位成员建立独立健康档案，上传报告时系统能自动识别归属到正确的人，以便多人的数据互不混淆、各自独立。

## What Changes

- 新建开源项目，本地私有化部署，单实例服务一个家庭
- 引入多模态大模型驱动的健康数据结构化能力：手动录入、报告导入（图片/PDF）、聊天抽取回填三种数据入档路径
- 建立人维度健康画像（A-H 全字段族），作为单一事实来源支撑上层所有服务
- 建立意图路由 + 工具调用的 AI 咨询框架，覆盖六类健康意图，角色知识边界约束兜底边界外问题
- 提供第一梯队生理指标（血压/血糖/血脂/心率/体重BMI）的趋势可视化与异常标识
- 模型层抽象：多模态 API（必选）、文字 API（可选）、本地 LLM（可选）三类 provider 可插拔
- WebUI 为主界面承载完整功能；飞书渠道作为资料收集与轻问答入口
- 家庭多成员档案管理，数据隔离，报告归属支持默认本人 + 多模态姓名识别 + 手动覆盖

## Capabilities

### New Capabilities
- `health-profile`: 健康画像与数据管理，包括 A-H 字段族定义、数据入档（手动/报告/聊天抽取）、数据溯源、家庭成员管理
- `report-ingestion`: 报告导入与多模态抽取，包括图片/PDF 上传、模型路由（视觉->多模态、文字->文字模型）、结构化抽取、姓名识别与归属匹配
- `ai-consultation`: AI 健康咨询，包括意图路由器、工具调用框架、六类意图实现、角色知识边界约束、聊天抽取回填闭环
- `visualization`: 健康数据可视化，包括第一梯队指标趋势图、异常标识、画像看板
- `channels`: 多渠道接入，包括 WebUI 主界面、飞书适配（资料收集+轻问答）、渠道适配层抽象
- `model-provider`: 模型层抽象，包括多模态 API/文字 API/本地 LLM 三类 provider 及路由逻辑

## Impact

- 全新项目，无历史代码影响
- 外部依赖：多模态大模型 API（如 OpenAI GPT-4o / 讯飞星火 / DeepSeek 等兼容接口）、飞书开放平台 API
- 数据层：需要结构化存储（SQLite 或 Postgres）+ 向量数据库（用于自由文本检索）
- 部署：Docker 化部署，开发者需自备模型 API key 或本地 LLM 环境
- 开源合规：需明确隐私声明——健康数据存本地，但对话内容会发往模型 API（除非切本地 LLM）
