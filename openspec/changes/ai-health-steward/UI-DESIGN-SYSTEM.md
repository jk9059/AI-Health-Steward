# 本地 AI 健康管家 - UI 设计系统规范

> 基于 MediUI Design System 适配，面向家庭健康场景的 WebUI 设计规范。
> 生成日期：2026-07-22

---

## 1. 设计目标与场景假设

### 设计目标
- 可靠：健康数据操作有明确确认与反馈，降低误操作
- 清爽：高信息密度下保持结构化、可扫描，家庭用户非专业医务人员
- 专业：视觉克制可信，传递健康数据的严肃性
- 安全：高风险操作（删除成员、删除记录）有二次确认路径

### 场景假设
- 用户：家庭健康管理者，非医务人员，技术素养中等
- 设备：桌面浏览器为主（Chrome/Safari/Firefox/Edge 100+），移动端可查看
- 使用频率：低频但长会话——偶尔上传报告、查看趋势，偶尔咨询
- 数据敏感度：高——健康数据涉及隐私，异常指标需突出展示

### 与传统医疗后台的差异
- 无处方开具、无病历审核流程、无就诊卡号
- 核心场景是"看自己的数据"而非"管理患者"
- AI 对话是核心交互，传统医疗后台无此模块
- 家庭多成员切换是特色，传统后台无此需求

## 2. Design Token 与全局规则

### 2.1 色彩系统

沿用 MediUI Foundation token，本项目的语义映射：

| Token | 值 | 本项目用途 |
|-------|-----|-----------|
| `--health-color-primary` | `#3363FF` | 主操作色（保存、确认、发送对话） |
| `--health-color-primary-light` | `#E6EDFF` | 选中态背景、激活标签 |
| `--health-color-medical-primary` | `#0891B2` | 健康指标正常色 |
| `--health-color-medical-success` | `#059669` | 指标正常标识 |
| `--health-color-medical-light` | `#ECFEFF` | 健康摘要卡片背景 |
| 成功色 `#67C23A` | — | 操作成功反馈 |
| 警告色 `#E6A23C` | — | 指标异常（偏高/偏低）标识 |
| 错误色 `#F56C6C` | — | 指标危急值、删除操作、S 级风险提示 |
| 信息色 `#909399` | — | 数据来源标签、辅助信息 |

### 2.2 医疗专用映射

| 场景 | 色彩 | 说明 |
|------|------|------|
| 指标正常 | `#059669` (medical-success) | 趋势图正常数据点、画像看板正常项 |
| 指标异常 | `#E6A23C` (警告) | 超出参考范围的数据点 |
| 指标危急值 | `#F56C6C` (错误) | 收缩压>180 等危急值，触发主动预警 |
| S 级风险内容 | `#F56C6C` + 禁止图标 | AI 拒绝输出的内容标识 |
| A 级风险内容 | `#E6A23C` + 警示图标 | AI 回答附带高风险警示 |
| B 级风险内容 | 默认色 | 常规科普，无额外标识 |
| 数据来源-手动 | 信息色 | Badge 标注"手动录入" |
| 数据来源-报告 | 主色 | Badge 标注"报告导入" |
| 数据来源-聊天 | 医疗辅助色 | Badge 标注"聊天抽取" |

### 2.3 排版与间距

沿用 Foundation token，本项目重点：
- 字体：`PingFang SC`, `Microsoft YaHei`, `Noto Sans SC`（中文优先）
- 指标数值用 mono 字体展示（`SF Mono` / `Consolas`），便于对齐
- 卡片圆角 `12px`，输入框 `8px`，按钮 `8px`
- 间距基准：`xs(4px)` / `sm(8px)` / `base(12px)` / `md(16px)` / `lg(20px)` / `xl(24px)`

### 2.4 响应式规则

| 断点 | 宽度 | 布局 |
|------|------|------|
| `sm` | 640px | 单列，侧边栏隐藏（抽屉模式），成员切换下拉 |
| `md` | 768px | 单列，侧边栏折叠为图标 |
| `lg` | 1366px | 双列，侧边栏展开，主内容区 |
| `xl` | 1440px | 双列+留白 |
| `2xl` | 1600px | 双列+更多留白 |

## 3. 原子组件规范

按 MediUI Atomic 模板，仅定义本项目有特殊要求的组件。未列出的组件（Switch / Checkbox / Radio / Progress 等）沿用 Foundation 默认规范。

### 3.1 MetricValue（指标数值展示）

核心功能：展示单个健康指标数值，含单位、参考范围、异常标识。

核心元素：
- 指标名称（Text，sm，regular）
- 数值（Text，2xl，600，mono 字体）
- 单位（Text，sm，secondary）
- 异常标识（Badge：正常/偏高/偏低/危急）
- 参考范围（HelperText，xs，secondary）

状态规则：
- 正常：数值用 medical-success 色
- 异常偏高：数值用警告色
- 异常偏低：数值用警告色
- 危急值：数值用错误色 + 闪烁动画（遵守 prefers-reduced-motion）
- 无数据：显示"暂无数据"占位

交互逻辑：
- 触发条件：悬停数值
- 执行动作：展示 Tooltip 含参考范围详情和数据来源
- 结果反馈：Tooltip 显示"参考范围: 90-120 mmHg / 来源: 报告导入 2026-07-15"
- 异常处理：参考范围缺失时 Tooltip 显示"参考范围缺失"

字段规范：
- `metricName: string`
- `value: number | null`
- `unit: string`
- `referenceLower: number | null`
- `referenceUpper: number | null`
- `isAbnormal: boolean`
- `isCritical: boolean`
- `sourceType: enum`
- `measuredAt: datetime`

### 3.2 ChatBubble（对话气泡）

核心功能：展示 AI 咨询对话的单条消息。

核心元素：
- 角色标识（用户/AI，Avatar + 名称）
- 消息内容（Text，支持 Markdown 渲染）
- 风险标签（Badge：S/A/B 级，仅 AI 消息）
- 免责声明（HelperText，xs，secondary，仅 AI 消息）
- 工具调用标识（Badge："已查询血压数据"，仅 AI 消息）
- 时间戳（Text，xs，secondary）

状态规则：
- 用户消息：右对齐，主色背景，白色文字
- AI 消息-正常：左对齐，白色背景，边框
- AI 消息-S 级：左对齐，错误色边框 + 禁止图标
- AI 消息-A 级：左对齐，警告色边框 + 警示 Badge
- AI 消息-B 级：左对齐，默认样式
- AI 消息-高危预警：顶部红色横条"建议立即就医"
- 加载中：左对齐，骨架屏 + "AI 思考中..." + 流式输出动画
- 发送失败：右对齐，错误色边框 + 重试按钮

交互逻辑：
- 触发条件：AI 消息加载中
- 执行动作：流式输出文字，逐字渲染
- 结果反馈：完成后展示完整消息 + 风险标签 + 工具调用标识
- 异常处理：API 失败时显示"AI 服务暂时不可用" + 重试按钮，对话历史保留

字段规范：
- `role: enum (user | assistant)`
- `content: string`
- `riskLevel: enum (S | A | B | null)`
- `toolCalls: array | null`
- `disclaimer: boolean`
- `isHighRiskAlert: boolean`
- `timestamp: datetime`
- `status: enum (sending | streaming | complete | error)`

### 3.3 MemberSwitcher（成员切换器）

核心功能：在家庭多成员间切换当前操作上下文。

核心元素：
- 当前成员 Avatar + 姓名
- 下拉列表（全部家庭成员）
- 每个成员的异常指标数 Badge

状态规则：
- 默认：显示当前选中成员
- 展开：下拉列表，每项含 Avatar + 姓名 + 异常指标数
- 切换中：加载态
- 空家庭：显示"请先添加家庭成员" + 添加按钮

交互逻辑：
- 触发条件：点击成员切换器
- 执行动作：展开下拉列表
- 结果反馈：选择成员后，所有页面数据切换到该成员上下文
- 异常处理：切换失败时回退到原成员并提示

字段规范：
- `members: array`
- `currentMemberId: string`
- `onChange: function`

### 3.4 ReportUploadCard（报告上传卡片）

核心功能：拖拽或点击上传健康报告图片/PDF。

核心元素：
- 上传区域（虚线框，dashed border）
- 上传图标
- 提示文案（"拖拽报告到此处，或点击选择文件"）
- 支持格式说明（"JPG / PNG / PDF，最大 20MB"）

状态规则：
- 默认：虚线框 + 图标 + 提示
- 悬停（拖拽中）：主色虚线框 + 主色浅色背景
- 上传中：进度条 + "上传中..."
- 抽取中：旋转图标 + "AI 识别中..."
- 待确认：成功图标 + "抽取完成，请确认" + 查看按钮
- 抽取失败：错误图标 + "抽取失败" + 重试按钮
- 文件过大：错误图标 + "文件超过 20MB 限制"
- 格式不支持：错误图标 + "仅支持 JPG/PNG/PDF"

交互逻辑：
- 触发条件：拖拽文件到上传区域 或 点击选择文件
- 执行动作：文件上传 → 多模态抽取 → 展示抽取结果确认
- 结果反馈：抽取完成后展示"待确认"状态，引导用户确认
- 异常处理：按状态规则中各错误态展示对应提示

字段规范：
- `accept: string = "image/jpeg,image/png,application/pdf"`
- `maxSize: number = 20971520`
- `status: enum (idle | uploading | extracting | pending | failed | error)`
- `reportId: string | null`
- `onConfirm: function`
- `onRetry: function`

## 4. 组合组件规范

### 4.1 MetricTrendChart（指标趋势图组合）

原子组件构成：
- MetricValue（当前最新值）
- 折线图（Chart 组件）
- Badge（异常标识）
- Tooltip（数据点详情）
- Button（时间范围切换：7天/30天/全部）

核心功能：展示某项生理指标的历史趋势，标识异常点。

结构规范：
- 顶部：指标名称 + 最新值（MetricValue） + 时间范围切换按钮
- 中部：折线图区域，高度 240px
- 底部：异常点摘要（"3 次偏高，1 次危急值"）

交互流程：
- 用户选择时间范围 → 图表刷新数据
- 悬停数据点 → Tooltip 展示数值/参考范围/来源/时间
- 点击异常点 → 展开该次测量的详情

状态与校验：
- 正常数据点：medical-success 色
- 异常数据点：警告色 + 放大
- 危急值数据点：错误色 + 放大 + 脉冲动画
- 无数据：空状态"暂无数据，上传报告或手动录入后可查看趋势"
- 加载中：骨架屏

异常处理：
- 数据加载失败：图表区域显示错误 + 重试按钮
- 参考范围缺失：图表不画参考范围线，Tooltip 标注"参考范围缺失"

### 4.2 ProfileDashboard（画像看板组合）

原子组件构成：
- Card（看板容器）
- MemberSwitcher
- MetricValue（各指标最新值，多个）
- Badge（异常项标识）
- Divider（字段族分隔）
- Collapse（可折叠的字段族区块）

核心功能：聚合展示某成员的健康画像全貌。

结构规范：
- 顶部：成员切换器 + 基础信息摘要（姓名/性别/年龄/BMI）
- 第一区：关键指标卡片网格（血压/血糖/血脂/心率/体重，每个一个 MetricValue + 缩略趋势）
- 第二区：异常项列表（高亮展示，错误色 Badge）
- 第三区：近期诊断与用药（可折叠）
- 第四区：过敏与禁忌（可折叠，醒目展示）
- 第五区：生活方式与家族史（可折叠）

交互流程：
- 用户进入看板 → 加载该成员全部画像数据
- 点击指标卡片 → 跳转到该指标的完整趋势图
- 点击异常项 → 跳转到对应指标趋势图并高亮异常点
- 展开折叠区 → 查看该字段族详情

状态与校验：
- 加载中：骨架屏
- 新数据入档：下次访问反映最新数据，不使用缓存
- 空画像（新成员）：引导"上传报告或手动录入开始建立健康画像"

异常处理：
- 加载失败：局部重试，不强刷整页
- 某字段族无数据：显示"暂无数据"

### 4.3 ChatPanel（AI 咨询对话面板）

原子组件构成：
- ChatBubble（消息列表）
- TextArea（输入框）
- Button（发送）
- Badge（风险标签）
- Dialog（聊天抽取确认弹窗）

核心功能：用户与 AI 进行健康咨询对话。

结构规范：
- 顶部：对话标题 + 当前成员标识
- 中部：消息列表（滚动区域），按时间正序
- 底部：输入框 + 发送按钮

交互流程：
- 用户输入消息 → 点击发送/回车
- 意图路由（function calling）→ 工具调用 → 流式输出回答
- 聊天抽取触发 → 弹出确认弹窗 → 用户确认/修改/拒绝 → 入档反馈
- 高危信号检测 → 回答顶部推送"建议立即就医"

状态与校验：
- 发送中：输入框禁用 + 发送按钮加载态
- AI 回答中：流式输出 + 骨架屏占位
- 抽取确认：弹窗展示识别到的数据，用户可编辑后确认
- API 失败：消息列表保留，显示重试按钮

异常处理：
- 模型 API 不可用：提示"AI 服务暂时不可用"，对话历史保留
- 意图识别错误：用户说"不对"触发重新路由
- 空数据查询：AI 回答"您还没有XX数据，建议先上传报告"

### 4.4 ReportConfirmPanel（报告抽取确认面板）

原子组件构成：
- Card（抽取结果容器）
- Badge（报告类型、归属成员）
- MetricValue（抽取到的各指标）
- TextInput / NumberInput（可编辑修正）
- Button（确认入档 / 拒绝 / 重新归属）

核心功能：展示多模态抽取结果，供用户确认或修正后入档。

结构规范：
- 顶部：报告类型 Badge + 归属成员选择器 + 报告日期
- 中部：抽取到的结构化数据列表（按字段族分组），每条可编辑
- 底部：确认入档 / 拒绝 / 重新归属 按钮

交互流程：
- 抽取完成 → 展示结果
- 用户检查 → 可直接编辑修正任何字段
- 用户选择归属成员（可覆盖自动识别）
- 点击确认 → 数据入档 + 溯源记录
- 点击拒绝 → 报告标记"已拒绝"，保留原始文件

状态与校验：
- 待确认：正常展示
- 确认中：按钮加载态
- 确认成功：跳转到画像看板，展示新增数据
- 确认失败：保留面板内容，提示重试

异常处理：
- 入档失败：保留确认面板全部内容，提示"入档失败，请重试"
- 抽取结果为空：提示"抽取结果为空，建议手动录入" + 手动录入入口

### 5.2 核心页面清单

| 页面 | 路由 | 核心组件 | 业务目标 |
|------|------|---------|---------|
| 画像看板 | `/` | ProfileDashboard | 一眼看到全家健康全貌 |
| AI 咨询 | `/chat` | ChatPanel | 与 AI 对话咨询健康问题 |
| 报告管理 | `/reports` | ReportUploadCard + List | 上传报告、查看导入历史 |
| 报告确认 | `/reports/:id/confirm` | ReportConfirmPanel | 确认抽取结果后入档 |
| 指标趋势 | `/metrics/:name` | MetricTrendChart | 查看单项指标历史趋势 |
| 成员管理 | `/members` | Form + List | 添加/编辑/删除家庭成员 |
| 系统设置 | `/settings` | Form | 模型配置、渠道配置、参考范围查看 |

### 5.3 关键交互链路

**链路1：上传报告 → 确认 → 看画像**
```
报告管理页 → 拖拽上传(ReportUploadCard) → 抽取中 → 待确认
  → 报告确认页(ReportConfirmPanel) → 编辑修正 → 选择归属 → 确认入档
  → 跳转画像看板(ProfileDashboard) → 看到新增数据
```

**链路2：AI 咨询 → 聊天抽取 → 确认入档**
```
AI咨询页(ChatPanel) → 用户输入"我今天测了血压130/85"
  → AI识别聊天抽取意图 → 弹出确认弹窗(Dialog)
  → 用户确认 → 数据入档 → AI回复"已记录您的血压数据"
  → 画像看板可看到新数据
```

**链路3：查看趋势 → 发现异常 → 咨询 AI**
```
画像看板(ProfileDashboard) → 点击血压卡片 → 指标趋势页(MetricTrendChart)
  → 发现异常点 → 点击异常点查看详情
  → 跳转AI咨询 → "我最近血压偏高怎么办"
  → AI基于画像回答 + 免责声明
```

## 6. 交互闭环与异常处理

### 6.1 组件状态矩阵

## 7. 响应式、可访问性与验收清单

### 7.1 响应式要求

| 断点 | 画像看板 | AI 咨询 | 报告管理 | 趋势图 |
|------|---------|---------|---------|--------|
| <640px | 单列堆叠，指标卡片全宽 | 全宽，输入框置底 | 上传卡片全宽 | 全宽，高度 180px |
| 640-1024px | 指标卡片 2 列 | 全宽 | 上传卡片全宽 | 全宽，高度 200px |
| 1024-1440px | 指标卡片 3 列 | 居中 max-800px | 上传卡片居中 | 全宽，高度 240px |
| >1440px | 指标卡片 4 列+留白 | 居中 max-800px | 上传卡片居中 | 全宽，高度 240px |

### 7.2 可访问性要求

- 颜色对比度不低于 4.5:1（异常标识不能只靠颜色，必须附文字）
- 焦点状态必须可见（焦点环 color: `--health-border-color-focus`）
- 所有图片有 alt 文本（报告缩略图 alt 含报告类型和日期）
- 表单有明确标签（手动录入表单每个字段有 label）
- 键盘导航可完成核心流程（Tab 切换、Enter 发送对话、Esc 关闭弹窗）
- 触摸目标不小于 40x40px（移动端成员切换、按钮）
- 加载态禁止重复提交（上传、确认入档、发送对话）
- 处理 prefers-reduced-motion（危急值脉冲动画降级为静态标识）
- 不允许无意义横向滚动（趋势图移动端可横向滚动，属有意义的）

### 7.3 验收清单

**设计交付前检查：**
- [ ] 无 emoji 图标，图标来自一致图标集（Material Symbols Outlined）
- [ ] 悬停状态无布局偏移
- [ ] 所有可点击元素有 cursor: pointer
- [ ] 过渡平滑并可降级（prefers-reduced-motion）
- [ ] 焦点状态可见
- [ ] 响应式覆盖 375px / 768px / 1024px / 1440px
- [ ] 每个组件覆盖默认/悬停/按下/聚焦/禁用/加载/错误状态
- [ ] 高风险操作有二次确认
- [ ] 异常场景有兜底反馈
- [ ] AI 输出有风险分级标识
- [ ] 数据来源可追溯展示
- [ ] 中文字体优先（PingFang SC / Microsoft YaHei）
- [ ] 指标数值用 mono 字体
